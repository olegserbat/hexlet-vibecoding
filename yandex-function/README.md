# Запись заявок в таблицу на Яндекс Диске

Простой бэкенд на Yandex Cloud Functions: принимает вебхук от Яндекс Форм
и дописывает строку в существующий xlsx-файл на Яндекс Диске.

```
Лендинг (iframe формы) → Яндекс Формы → HTTP-вебхук → Cloud Function → Яндекс Диск (xlsx)
```

Все шаги ниже выполняются в вашем аккаунте Яндекса — доступа к нему у меня
нет и быть не должно, поэтому это ручная инструкция, а не то, что я могу
сделать сам.

## 1. Получить OAuth-токен для Яндекс Диска

1. Откройте https://oauth.yandex.ru/ → **Создать приложение**.
2. Платформа — «Веб-сервисы», Redirect URI можно указать любой (например
   `https://oauth.yandex.ru/verification_code`), для получения токена вручную
   он не используется.
3. В разделе «Яндекс.Диск REST API» отметьте права **на чтение всего Диска**
   и **на запись в любом месте на Диске** — не ограничивайтесь правами
   «Доступ к папке приложения», иначе функция не увидит существующий файл.
4. Сохраните приложение, затем на странице приложения возьмите его
   **ClientID** и откройте
   `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>`
   — после подтверждения в адресной строке будет `access_token=...`. Это и
   есть токен для `YANDEX_DISK_TOKEN`.
5. Токен даёт полный доступ к Диску — храните его только в переменных
   окружения функции, никогда не в репозитории и не в переписке.

## 2. Определить путь к файлу на Диске

`DISK_FILE_PATH` — это путь файла *в файловой структуре Диска*, а не
публичная ссылка вида `disk.yandex.ru/i/...`. Обычно это просто
`/Запись на прием (тест).xlsx`, если файл лежит в корне Диска, либо
`/Папка/Запись на прием (тест).xlsx`, если он в подпапке — посмотрите путь
в приложении Диска (Правой кнопкой → «Скопировать путь», либо просто по
расположению файла в списке папок).

## 3. Создать функцию в Yandex Cloud

1. https://console.yandex.cloud/ → **Cloud Functions** → **Создать функцию**.
2. Среда выполнения — **Python 3.12**.
3. Загрузите содержимое этой папки (`function.py` и `requirements.txt`) —
   зависимости будут установлены автоматически при сборке версии.
4. Точка входа: `function.handler`.
5. Таймаut — 10–15 секунд достаточно.
6. Переменные окружения версии функции:
   - `YANDEX_DISK_TOKEN` — токен из шага 1
   - `DISK_FILE_PATH` — путь из шага 2
   - `WEBHOOK_SECRET` — произвольная строка, придумайте сами (например,
     сгенерируйте `openssl rand -hex 16`); нужна, чтобы форму не мог дёргать
     кто попало, зная только адрес функции
7. Сохраните и опубликуйте версию.
8. Включите **публичный доступ** функции (или создайте HTTP-триггер) —
   получите вызывной URL вида `https://functions.yandexcloud.net/<id>`.

## 4. Настроить вебхук в Яндекс Формах

1. Откройте форму в редакторе (не публичную ссылку) → вкладка
   **Интеграции**.
2. Добавьте действие → **API** → **Отправить HTTP-запрос**.
3. Метод — `POST`, URL — адрес функции из шага 3.8.
4. Если в интерфейсе есть поле для заголовков — добавьте
   `X-Webhook-Secret: <ваш секрет>`. Если заголовков нет, допишите секрет
   параметром в URL: `...?secret=<ваш секрет>`.
5. Content-Type — `application/json`, тело запроса:

   ```json
   {
     "name": "<переменная: ответ на вопрос «Имя»>",
     "phone": "<переменная: ответ на вопрос «Телефон»>",
     "email": "<переменная: ответ на вопрос «Почта»>",
     "visit_date": "<переменная: ответ на вопрос «Дата визита»>",
     "reason": "<переменная: ответ на вопрос «Причина обращения»>"
   }
   ```

   Каждую переменную вставляйте через иконку выбора переменной у поля —
   не печатайте текст руками. Для каждой выберите фильтр **JSON**, чтобы
   спецсимволы и переносы строк не ломали запрос.

6. Сохраните действие.

## 5. Проверить

1. Отправьте тестовую заявку через лендинг или напрямую через форму.
2. В консоли Cloud Functions откройте **Логи** — там будет видно, прошёл ли
   вызов и с каким кодом ответа.
3. Откройте файл на Диске — должна появиться новая строка. При первом
   успешном запуске функция сама допишет заголовки колонок в первую строку.

## Ограничения

- Функция не блокирует файл на время записи: если две заявки прилетят
  практически одновременно, теоретически возможна потеря одной из строк
  (redownload-modify-upload гонка). Для тестового проекта с низкой
  нагрузкой это не критично; для боевого сценария нужна была бы очередь
  или блокировка.
- OAuth-токен даёт доступ ко всему Диску, а не только к одному файлу —
  это ограничение самого Disk API, у которого нет токенов с доступом к
  отдельному файлу за пределами папки приложения.
